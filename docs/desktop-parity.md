# Desktop and Web reliability comparisons

This comparison covers implemented Terngram workflows, not complete Telegram Desktop parity or API Terms compliance. The current backend uses Python and the official native TDLib C JSON API; the previous transport is [legacy-only](https://github.com/d3d0n/terngram/tree/legacy). Desktop `dev` and Web A `master` links are moving references, not pinned implementation audits.

Use [backend.md](backend.md) for RPC/storage/outbox contracts, [ui.md](ui.md) for interaction/state behavior, [tern-api.md](tern-api.md) for host capabilities, and [security.md](security.md) for privacy, the full Terms matrix, sponsored requirements, and qualified transport evidence.

## Outcomes, invariants, and remaining differences

| Workflow and reference | Terngram outcome / invariant | Remaining difference |
| --- | --- | --- |
| **Send identity and ambiguous completion** — Desktop [api_sending.cpp](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/api/api_sending.cpp) separates local outgoing identity from transport completion. | `prepare_send` durably allocates an intention before UI persistence and native submission. TDLib owns the network outbox. Prepared means not submitted; queued means not confirmed. Send-success/failure updates reconcile identity; ambiguous submission is never automatically resent. Monotonic tokens and content-free terminal tombstones survive restarts. [Service](../terngram/telegram.py), [UI send flow](../terngram/ui/app.ts). | No exactly-once guarantee or complete background offline UI queue. Retry requires confirmed failure/retry permission. Explicit abandon stops tracking; it does **not** cancel possible server delivery. |
| **Draft, reply, and edit** — Desktop [data_drafts.cpp](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/data/data_drafts.cpp) distinguishes cloud drafts, local edit drafts, reply, and cursor. | Switching chats retains in-process text/modes. Cancel edit restores the previous draft/reply. Late send completion does not clear newer typed text. Atomic private JSON preserves draft text and pending-send reply. [Chat state](../terngram/ui/chat-state.ts), [app persistence](../terngram/ui/app.ts). | Ordinary reply/edit/cursor are not restored across launches; no cloud draft synchronization. This is not full draft parity. |
| **Reads and visibility** — Desktop [data_histories.cpp](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/data/data_histories.cpp) separates requested/sent boundaries; [history_widget.cpp](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/history/history_widget.cpp) uses scroll/window state. Web A [useMessageObservers](https://github.com/Ajaxy/telegram-tt/blob/master/src/components/middle/hooks/useMessageObservers.ts) observes visible message markers and excludes quick preview; [useBackgroundMode](https://github.com/Ajaxy/telegram-tt/blob/master/src/hooks/window/useBackgroundMode.ts) tracks foreground focus. | [ReadReceipts](../terngram/ui/read-receipts.ts) uses requested/confirmed maxima and one in-flight call per chat. Newly arriving IDs cannot expand an existing request without a new read decision; errors do not advance frontend confirmation. Latest/successful-send paths return to the end. Backend state and outgoing receipts follow TDLib read updates. | No visible-message boundary or pane-activity event reaches the app. Recent input (60 seconds) and detached-history state are heuristics, not actual reading. Surface `visible`, keyboard focus, `reveal=end`, and protocol acknowledgement do not prove painted visibility. |
| **History and live edits/deletions** — Desktop [history.cpp](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/history/history.cpp) and [data_histories.cpp](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/data/data_histories.cpp) keep the model separate from rendering. | Revision-aware history merge preserves newer live edits/deletions during a request. Short TDLib cache pages are refilled until the requested page or EOF; cursors use current chat/message IDs, not legacy peer/date transport offsets. [Chat state](../terngram/ui/chat-state.ts), [service](../terngram/telegram.py). | TDLib's database does not supply a full offline-history UI, viewport eviction, or bounded history model by itself. |
| **Albums across page boundaries** — Desktop [data_groups.cpp](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/data/data_groups.cpp) and [group thumbnails](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/media/view/media_view_group_thumbs.cpp) use a group context beyond one page. | The worker scans neighboring chat history and checks album membership/completeness before gallery or bulk forward/delete. The UI reuses resolved composition until invalidation; mutation rechecks it on the backend. | Contiguous albums of at most ten members; unavailable/incomplete resolution fails rather than performing a partial mutation. No gallery over all shared-media history. |
| **Preview versus original** — Desktop [group thumbnail loading](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/media/view/media_view_group_thumbs.cpp) requests thumbnails separately from full media. | Photo previews choose a Telegram size around 320 px. Documents without supported thumbnails do not auto-download their originals, regardless of size. Up to four inline previews per group, preview concurrency two; explicit full open is separate. [Loader](../terngram/ui/image-loader.ts), [service](../terngram/telegram.py). | The queue covers loaded history in the current chat, not visible viewport intersections. No user-configurable auto-download policy. Protected/temporary media remains permission-gated; see [security](security.md). |
| **Media replacement and gallery selection** — Desktop [data_photo.cpp](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/data/data_photo.cpp) tracks resource/cache lifecycle; [media_view_overlay_widget.cpp](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/media/view/media_view_overlay_widget.cpp) owns current selection/caption/navigation. | Media identity invalidates old loader entries; version fences prevent stale downloads from publishing. A newer open/cancel intent defeats late old responses. Gallery opens the chosen member, preserves selection by message identity, and provides arrows, index/count, and caption. [Photo viewer](../terngram/ui/photo-viewer.ts), [app](../terngram/ui/app.ts). | Full album photos load together. Overlay `lg` is a semantic hint; zoom/geometry are host-owned. No SDK blob-drop API or proven host-byte release after expiry/cache removal. |
| **Local search and metadata freshness** — Desktop [IndexedList filtering](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/dialogs/dialogs_inner_widget.cpp), [server-search cache](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/dialogs/dialogs_widget.cpp), [peer photo updates](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/data/data_peer.cpp), and [member-count updates](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/data/data_channel.cpp). | Palette search filters the local dialog catalog, shares sequential page fetches, and does not restart exhausted pagination after a first-page refresh. Specific TDLib chat/user/group updates update titles or invalidate affected avatar/full-info/permissions; request identity blocks stale metadata. Switching chats drops unstarted preview/avatar jobs while retaining ready/active entries. [Palette](../terngram/ui/command-palette.ts), [app](../terngram/ui/app.ts), [service](../terngram/telegram.py). | No global peer or message search. Avatar fallback is initials when metadata/photo is unavailable—not invented imagery or arbitrary global lookup. Full-info and metadata remain subject to Telegram access/privacy. |
| **Server-directed waits** — Telegram assigns dynamic limits, not a fixed safe client request rate. | [RequestCooldowns](../terngram/ui/request-cooldowns.ts) applies Flood/FloodPremium per method and SlowMode per method+peer before writing another RPC. A later shorter wait cannot shorten the deadline; replacing the worker preserves account cooldowns. No automatic resend. | Cooldowns do not guarantee that FloodWait cannot happen or that an account cannot be restricted. |
| **Reader count** — Desktop [WhoReadExists / WhoReadIds](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/api/api_who_reacted.cpp) applies eligibility/privacy/size/expiry restrictions and uses returned participants. | UI selects an own already-read group message, waits 300 ms of stable selection, then displays the cardinality of actual TDLib `getMessageViewers`. Backend delegates eligibility to `getMessageProperties.can_get_viewers`. [Reader cache](../terngram/ui/reader-counts.ts), [app](../terngram/ui/app.ts), [service](../terngram/telegram.py). | No bulk requests or polling; per-message refresh is at least 30 seconds, longer after server waits. Unavailable is null, not “0”. UI shows a number, not a participant-list surface; Telegram controls privacy/age/size eligibility. |
| **Keyboard context and error ownership** — Desktop separates editing, message selection, modal confirmation, and operation errors. | Enter sends only from the editor, replies from message focus, and confirms only explicit delete/logout contexts. Esc closes the top surface; message shortcuts do not steal editor text. Background deletion/empty Escape do not reset caret; losing write permission preserves drafts and moves focus out of the absent editor. Errors identify operation/safe code; private diagnostics omit values/secrets. | Real Tern focus, geometry, and usability need host-surface observation. Native protocol frames do not prove final rendering or live network compatibility. |

## What carries over from the reference clients

1. **Identity beats repetition:** a send intention, requested read boundary, media identity, and viewer intent each have an explicit lifetime.
2. **The model is larger than a visible page:** bulk album actions require complete server-side composition.
3. **Late replies cannot overwrite newer state:** revision, request identity, connection/account generation, and download-version checks preserve current decisions.
4. **A preview is not an original; queued is not confirmed:** thumbnail retrieval and explicit full open are distinct, just as request completion differs from server send confirmation.
5. **Unavailable is not empty or successful:** failed reads, missing viewer eligibility, incomplete albums, and protected content preserve uncertainty instead of fabricating results.

## Evidence and non-parity boundaries

This document compares source contracts, not a record of completed test runs. Offline tests/native smoke can exercise race handling, auth fixtures, reconciliation, and protocol frames; they cannot prove live QR scanning/delivery, actual message visibility, sponsored impressions, protected-byte erasure, or final host layout. See [development](development.md) for checks and [security](security.md) for the preserved no-login ABI evidence and exact upstream-review provenance.

There is no complete Desktop feature set: unsupported attachments/player features, cloud draft sync, secret chats, global search, and other missing surfaces must remain explicit limitations. Official sponsored support is currently absent despite channel/bot access; fullscreen-video and global-search advertising requirements become applicable when those features are implemented. The full clause-by-clause status belongs in [security.md](security.md), not this comparison or the README.
